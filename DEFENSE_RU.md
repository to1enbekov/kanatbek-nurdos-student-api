# Краткий текст для защиты DevOps Midterm — Kanatbek Nurdos

## Часть 1: Linux
«Я создал структуру проекта из папок scripts, logs, backups, src и
необходимых файлов. Bash-скрипт с shebang `#!/usr/bin/env bash`
выводит имя, время, пользователя, ОС, kernel, CPU, RAM и информацию
о диске. Через `tee -a` он выводит сведения в консоль и дописывает
их в log. `chmod 744` даёт владельцу rwx, остальным — только чтение.
Я сделал backup README, проверил его командой diff, изучил процессы,
tail и grep. `>` перезаписывает файл, `>>` добавляет в конец».

## Часть 2: Git
«Я инициализировал репозиторий, создал .gitignore, сделал первый commit,
CRUD feature branch с двумя коммитами, слил в main. Затем специально
изменил одну строку README в двух ветках и получил настоящий merge
conflict. Вручную разрешил, закоммитил merge, создал version tag.
Git хранит историю локально; GitHub — удалённая платформа. Git branch
позволяет изолировать изменения. .env и секреты коммитить нельзя».

## Часть 3: Docker
«Я разработал CRUD API на Spring Boot и PostgreSQL. Multi-stage build
сначала компилирует JAR на JDK, потом запускает его в более компактном
JRE-контейнере. Compose управляет двумя сервисами: API и PostgreSQL;
API подключается по имени сервиса postgres внутри Docker network,
потому что localhost внутри контейнера указывает на него самого.
Named volume pgdata позволяет сохранить записи после рестарта. Я
демонстрирую POST, GET, PUT, DELETE и ошибку 404».

## Часть 4: Jenkins
«Jenkins читает Jenkinsfile и проходит стадии Checkout, Build, Test,
Docker Build и Verify. Если тест упадёт, pipeline не пойдёт дальше.
Я отдельно показал намеренную ошибку теста на тестовой ветке,
затем исправил её. Poll SCM регулярно проверяет Git и автоматически
запускает pipeline после нового commit. CI — интеграция и проверки,
CD бывает delivery и deployment, но развёртывание не требуется».

## Вопросы — короткие ответы

- **Docker image vs container:** образ — шаблон; контейнер — запущенный экземпляр.
- **Docker volume vs network:** volume хранит данные; network связывает сервисы.
- **RUN vs CMD:** RUN при сборке образа; CMD при запуске контейнера.
- **FROM:** задаёт базовый образ. **WORKDIR:** рабочая директория.
- **COPY vs ADD:** COPY переносит файлы; ADD поддерживает доп. функции.
- **EXPOSE:** документирует порт внутри контейнера.
- **docker stop vs rm:** stop останавливает; rm удаляет контейнер.
- **git add vs commit vs push:** индексирует, сохраняет локально, отправляет на remote.
- **fetch vs pull:** fetch скачивает ссылки/объекты; pull ещё интегрирует.
- **merge vs rebase:** merge сохраняет ветвление; rebase переписывает последовательность commit.
- **Merge conflict:** Git не смог автоматически объединить пересекающиеся правки.
- **git status:** состояние рабочей директории и staging area.
- **chmod 744:** `rwxr--r--`.
- **df -h:** место на диске; **free -h:** RAM/swap.
- **tail -n 5:** последние пять строк файла.
- **grep:** поиск по тексту.
- **Jenkins controller vs agent:** управляющий сервер и исполнитель.
- **Jenkins Credentials:** безопасное хранение секретов для jobs.
- **Webhook vs polling:** GitHub сообщает об изменениях vs Jenkins сам проверяет.
- **Healthcheck:** проверяет, что сервис готов; не только запущен.
- **pwd:** текущий путь. **mkdir -p:** создать все недостающие родительские папки.
- **Процесс:** выполняющаяся программа; `ps -ef`, `kill PID`.
- **JDK vs JRE:** JDK компилирует; JRE запускает Java-приложение.
- **PostgreSQL service name:** Docker DNS разрешает `postgres` в сети Compose.
- **Почему тесты перед Docker:** не собирать/распространять заведомо сломанный код.
